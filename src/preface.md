# Zig 编程语言全面入门教程
## ——写给有编程经验、想系统理解 Zig 的开发者

欢迎来到这本 Zig 教程。

这不是一本“快速背语法”的手册，而是一份以**理解语言设计、建立正确心智模型、逐步进入工程实践**为目标的入门教程。  
如果你已经写过 C、C++、Rust、Go、Java、Python 或其他主流语言，那么这本书最希望帮助你的，不只是“学会 Zig 怎么写”，而是理解：

- Zig 为什么这样设计
- Zig 和你熟悉的语言到底差在哪里
- 哪些地方需要你主动、更明确地表达意图
- 如何用 Zig 写出清晰、可控、可维护的代码

## 阅读这本书时，建议特别关注什么？

学习 Zig 时，建议你始终带着下面几个问题阅读：

### 这段代码的意图是否足够明确？
Zig 非常强调显式表达。  
很多在其他语言里可以“默认推断”或“习惯省略”的地方，在 Zig 中更鼓励你写清楚。

### 失败路径在哪里？
在 Zig 里，错误处理不是附属品，而是主流程设计的一部分。  
你需要习惯思考：

- 这一步会失败吗？
- 失败时由谁处理？
- 失败后资源是否能正确清理？

### 资源的生命周期是否清楚？
内存、文件句柄、网络连接、锁等都属于资源。  
Zig 希望你明确知道：

- 资源在哪里获取
- 资源由谁持有
- 资源在什么时候释放

### 这段代码是否容易读懂？
Zig 的很多设计都偏向“让代码更容易被读懂、被验证、被维护”。  
所以在学习过程中，不要只追求“能写出来”，也要注意“是否表达清楚”。

## 版本说明

> 本教程面向 **Zig 0.16.0-dev** 这一代 API 风格编写。  
> Zig 仍在积极演进中，开发版与稳定版之间可能存在语法和标准库差异。

阅读时请注意以下几点：

- 本书中的示例优先采用 **0.16 风格** 的标准库接口和项目组织方式
- 一些旧文章、旧博客、旧仓库中的写法，可能仍基于 `0.11`、`0.12`、`0.13`、`0.14` 或 `0.15`
- 如果你本地使用的是其他版本，示例代码可能需要做少量调整

### 本书中最值得留意的版本差异

#### `std.io` 与 `std.Io`
在较新的 0.16 开发版语境中，I/O 相关 API 已明显向 `std.Io` 这一套接口演进。  
如果你查阅的是旧资料，常常会看到 `std.io` 风格的写法。

#### `main` 函数写法更灵活，不只有一种签名
在 0.16 语境下，`std.process.Init` 相关写法是很常见的新风格之一，但它**不是唯一合法写法**。  
例如，无参数的 `main` 依然可能是完全合理的选择。

本书会根据示例目的，选用最容易解释的写法；在需要和 0.16 新接口配合时，也会使用带 `std.process.Init` 的形式。

#### 分配器相关 API 在持续演进
如果你查阅旧资料，可能会看到一些与当前版本不完全一致的分配器名称或用法。  
本书会尽量使用当前教程上下文中一致、便于理解的方式介绍，但你在对照外部资料时，要有“版本差异可能存在”的心理预期。

#### 异步能力的现状需要区别看待
Zig 早期曾提供语言内置的 `async` / `await` 机制，但这套方案后来已被移除。当前与异步相关的能力与实践路径仍在调整之中，整体方向也更偏向库层而非把它作为当前入门阶段的核心语言主线。  
因此，本书不会把“语言级 async/await”作为当前基础主线内容来讲，而会把重点放在更稳定、对入门更关键的语言基础与工程能力上。

## 关于代码示例

本书中的代码示例遵循几个原则：

### 优先讲清楚，再追求写法炫技
示例会优先选择：

- 容易读懂
- 便于解释
- 能体现语言设计意图

而不是一开始就展示最复杂、最“高级”的写法。

### 尽量使用当前版本语境下可理解的写法
对于版本敏感的标准库 API，本书会尽量：

- 直接给出当前语境下的推荐写法
- 在必要时提醒你这属于版本易变区域
- 避免把旧版和新版写法混在一起造成困扰

### 错误示例只用于教学对比
当你看到“错误示例”时，它的目的通常是：

- 帮你理解为什么某种写法不推荐
- 帮你辨认编译器在阻止什么问题
- 帮你建立 Zig 强调显式与安全的直觉

不要把这些示例当成可直接复制到生产代码中的做法。

## 学习 Zig 时，很正常会遇到这些“不适应”

如果你第一次接触 Zig，下面这些感受都很正常：

- “为什么很多地方都要我显式写出来？”
- “为什么错误处理不能随便略过？”
- “为什么资源管理这么强调责任边界？”
- “为什么编译器这么爱拦我？”

这不是 Zig 在“故意刁难人”，而是它的设计目标就是：

- 尽早暴露问题
- 让失败路径可见
- 让资源生命周期清楚
- 让性能和行为更可预测

一开始你可能会觉得它“啰嗦”；  
但当项目逐步变复杂时，这种明确性会越来越有价值。

读完基础篇后，如果你能够逐步形成下面这些习惯，这本书就达到目的了：

- 看到一个值时，会先想清楚它的类型与语义

- 设计一个函数时，会主动让接口表达清楚意图
- 遇到编译错误时，不把它当阻碍，而当成反馈

## 最后的建议

学习 Zig，不必急着“把所有高级特性一次吃透”。

更好的方式是：

1. 先把基础语法和核心模型学扎实
2. 每章示例都亲手敲一遍
3. 适当改参数、改输入、改结构，观察编译器反馈
4. 遇到版本差异时，先确认本地 Zig 版本
5. 把重点放在“理解设计意图”，而不只是“记忆写法”

只要你愿意接受 Zig 的这些原则：

- 显式表达意图
- 主动处理失败路径
- 对资源生命周期负责
- 优先写出清晰、可验证的代码

那么这门语言会越来越顺手。
