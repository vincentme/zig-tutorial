# 第一部分导读：从会写代码，到理解 Zig 的基本思维方式

第一部分的目标不是一次性讲完 Zig 的所有特性，而是帮助你建立一套**能够继续往下学**的基础心智模型：

- 知道 Zig 想解决什么问题，适合什么场景
- 能搭好开发环境，跑通最小程序
- 理解值、类型、控制流、函数、错误处理这些核心语法
- 能看懂并编写一个简单的 Zig 项目
- 为第二部分的 `comptime`、标准库、内存管理、C 互操作等主题做好准备

如果你已经有 C、C++、Rust、Go、Java、Python 等语言经验，那么这一部分最重要的不是“记住 Zig 语法细节”，而是逐步适应 Zig 的几个核心特点：

- **显式优于隐式**
- **把错误处理当作正常控制流的一部分**
- **资源管理要清楚地写出来**
- **类型系统帮助你在编译期尽早发现问题**
- **先写清楚，再谈抽象与高级技巧**

## 这部分适合怎么读？

建议你**按顺序阅读**，因为章节之间存在明显的依赖关系。

推荐顺序如下：

1. [认识 Zig：设计目标与学习路线](chapter-introduction.md)  
   先建立整体认识：Zig 想解决什么问题、适合什么场景，以及这一部分会先学什么、后学什么。

2. [开发环境与第一个程序](chapter-setup.md)  
   先把工具装好、把程序跑起来，再进入语法和工程细节，学习体验会顺畅很多。

3. [变量、常量与基础类型](chapter-basic-types.md)  
   这是后续所有语法的基础，包括 `const` / `var`、整数、浮点、布尔、字符串、类型转换等。

4. [函数定义与调用](chapter-functions.md)  
   先掌握函数签名、参数、返回值和基本组织方式，再去看更复杂的数据建模，会更容易跟上后面的示例。

5. [复合类型：数组、切片与数据建模](chapter-compound-types.md)  
   学习数组、切片、结构体、枚举等常见数据建模方式，建立“数据长什么样”的直觉。

6. [控制流、可选类型与资源管理](chapter-control-flow.md)  
   学习 `if`、`while`、`for`、`switch`、`defer` 等机制，理解 Zig 如何组织程序执行过程。

7. [错误处理：!T、try 与 errdefer](chapter-error-handling.md)  
   这是 Zig 最有辨识度的部分之一。建议在已经熟悉基本语法后，再集中理解失败路径与资源清理。

8. [构建系统入门](chapter-build-system.md)  
   把“单文件练习”升级为“项目化开发”，形成完整的基础开发闭环。

## 第一次阅读时，哪些内容要重点掌握？

如果你是第一次接触 Zig，建议优先掌握下面这些内容：

### 必须掌握

- `const` 和 `var` 的区别
- 基本数值类型与显式类型转换
- 数组与切片的区别
- `if`、`while`、`for`、`switch` 的基本写法
- 函数签名、参数、返回值
- 可选类型 `?T`
- 错误联合类型 `!T`
- `try`、`catch`
- `defer` 和 `errdefer` 的基本用途
- `zig run`、`zig test`、`zig build` 这几个日常命令

### 第一次阅读可以先“理解概念，不必死记”

- 非穷尽枚举
- 联合类型的进阶写法
- 一些偏底层的内存布局说明
- 与 C 兼容相关的细节
- 构建脚本中的高级配置项

换句话说，第一遍学习时，更重要的是你能回答这些问题：

- 这个值的类型是什么？
- 这段逻辑可能失败吗？
- 失败时谁来处理？
- 这块资源在什么时候释放？
- 这段代码是值语义还是引用语义？
- 这个 API 的意图是否足够明确？

## 学这一部分时，建议带着哪些问题去看？

为了让阅读更高效，你可以在每章里都主动思考下面几个问题：

### 1. 这门语言在逼我“显式表达”什么？

例如：

- 是否需要明确区分可变和不可变？
- 是否需要明确处理错误？
- 是否需要明确写出资源释放逻辑？
- 是否需要明确指出类型转换的意图？

这正是 Zig 的核心风格之一。

### 2. 这段代码的失败路径是什么？

在 Zig 中，失败路径不是边缘情况，而是主线设计的一部分。  
从基础篇开始养成这个习惯，后面学标准库、分配器、文件 I/O、网络时会轻松很多。

### 3. 这个值到底是“拥有数据”，还是“只是看见数据”？

例如数组和切片就体现了这类区别。  
很多初学者真正卡住的地方，不是语法不会写，而是**不知道自己到底是在复制数据，还是在引用已有数据**。

### 4. 这段代码是否容易读懂？

Zig 很强调“可读性优先于书写时的省事”。  
如果一段写法虽然短，但隐藏了意图，往往就不是 Zig 风格里最推荐的方式。

第一部分解决的是“**能读、能写、能运行、能理解基本模型**”的问题。

- `defer` / `errdefer`

- 值语义与资源所有权意识

## 学习建议

### 建议 1：每章都亲手敲代码

不要只看代码示例。  
Zig 是一门“看懂了不等于写对了”的语言，很多细节只有在你亲自编译时才会真正建立感觉。

### 建议 2：优先理解“为什么这样设计”

例如：

- 为什么没有异常？
- 为什么不鼓励隐式转换？
- 为什么资源释放要显式写出来？
- 为什么很多地方编译器会要求你把情况写全？

一旦理解设计动机，语法细节会容易记得多。

### 建议 3：遇到版本差异时，先回到前言看版本说明

Zig 仍在快速演进，尤其是开发版。  
如果你发现某段示例和你本地版本不一致，先不要急着怀疑自己，先确认版本，再判断是语法差异、标准库 API 变化，还是教程示例采用了本书当前统一的章节顺序与写法。

### 建议 4：第一次阅读不要追求“一次全懂”

基础篇里有些概念会在后文再次出现，并且理解会逐步加深。  
第一次读时，做到“能跟上主线、能跑通示例、知道每个机制解决什么问题”就已经很好。

## 学完这一部分后，你应该能做到什么？

完成第一部分后，理想状态下你应该已经可以：

- 独立搭建 Zig 开发环境
- 写出和运行简单的 Zig 程序
- 理解常见类型与控制流写法
- 能用函数组织代码
- 能处理可选值和显式错误
- 能看懂一个简单 Zig 项目的基本结构
- 能继续进入更深入的标准库、内存管理与工程实践主题

如果你已经达到这些目标，就可以继续进入第二部分；  
如果还不够稳，最好的方式不是反复重读，而是：

1. 重新敲一遍示例
2. 自己改一改参数和输入
3. 试着写几个小练习
4. 看看编译器报错在提醒你什么

## 一个推荐的练习方式

每读完一章，做一个很小的练习即可，例如：

- 学完变量和基础类型：写一个简单的单位转换器
- 学完复合类型：写一个学生信息或任务列表的数据结构
- 学完控制流：写一个命令行菜单或简单计算器
- 学完函数：把前面的逻辑拆成多个函数
- 学完错误处理：给读取、解析、计算过程加上错误分支
- 学完构建系统：把练习整理成一个完整项目

不要一开始就追求“大项目”。  
在 Zig 里，**把基础概念写清楚**，比过早堆复杂功能更重要。
